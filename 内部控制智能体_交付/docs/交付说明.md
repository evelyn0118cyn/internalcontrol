# 华诚集团内部控制评价智能体 · 交付说明

> 版本 V1.0　|　构建产物：`index.html`（单文件，双击即开、离线可用）　|　使用者：崔语凝（内控评价人员）

本目录是「内部控制智能体」项目的完整交付包。核心交付物是**一个 `index.html` 文件**：双击即可在浏览器打开并完成
「导入材料 → 120 个控制点逐点评估 → 缺陷分类与根因合并 → 风险矩阵加权评分 → 有效/无效结论 + 红色预警 → 四份成果下载」全流程，
无需安装依赖、无需启动服务器、无需配置环境。

---

## 一、快速开始

1. **双击 `index.html`**（推荐 Chrome / Edge / 新版 Safari 桌面浏览器，窗口宽度 ≥ 1024px）。
2. 首次打开会弹出**教学测试密钥提示**，点「我知道了」即可（可在「大模型API设置」中换成自己的密钥）。
3. 点「**载入示例材料（120 个控制点）**」→ 点「**▶ 开始逐点评估**」→ 约 1 秒内得到完整结论（演示数据）。
4. 正式使用时改用「上传 Excel / CSV」「粘贴文本」或「填表单」导入本集团真实材料。
5. 想快速验证引擎是否正常：点顶栏「**🧪 内嵌测试示例**」→「▶ 一键运行测试」，页面会把「预期输出」与「实际结果」并排比对（✅ / ❌）。

## 二、功能与 Prompt 要求对照

| Prompt 要求 | 实现位置 | 说明 |
|---|---|---|
| 120 个控制点逐个评估、不抽样 | 工作区「控制点评估表」 | 导入 120 个控制点即输出 120 行，覆盖率 100%，无跳号无重复 |
| 双维度 checklist（设计 4 项 + 运行 3 项） | 规则引擎 | 4 项全满足=设计有效；3 项全满足=运行有效；两项均有效=有效 |

| 同根因合并、保留关联控制点与合并前数量 | 「缺陷清单」 | 按「根因标签 + 责任部门 + 流程」聚类；列「涉及控制点数」与「关联控制点」 |
| 风险矩阵加权评分、重大缺陷权重 ≥ 一般 5 倍 | 工作区「评分明细」 | 权重 一般 1 / 重要 3 / 重大 8；逐步展示公式与代入数值 |
| 一票否决（有重大缺陷即判无效） | 「评价结论」+ 顶栏红色横幅 | 总分高低不影响结论 |
| 重大缺陷红色预警卡（6 项要素） | 「评价结论」页 | 缺陷描述 / 涉及控制点 / 法规依据 / 责任部门 / 整改建议 / 风险等级 |
| 结论含法规引用、内部制度引用、缺陷列举、评分明细 | 「评价结论」页 | 内置法规条款库 + 内部制度占位条款（可粘贴真实条款替换） |
| 四份成果一键下载 | 各成果右上角 + 右栏 | CSV、Excel、打印/保存为 PDF、一键下载全部成果（ZIP） |
| 同输入两次运行结果完全一致 | 规则引擎纯函数 | 固定四舍五入、固定排序、temperature=0.1；内嵌测试含「可复现」检查 |
| 大模型只做文字、不参与判定与评分 | 「大模型API设置」 | 调用失败自动降级，结论与评分不受影响 |
| 内嵌测试示例（12 个控制点） | 顶栏「内嵌测试示例」 | 预期输出固定展示，运行后与实际结果逐项比对 |

### 页面结构

- **顶部固定标题栏**：左「华诚集团内部控制评价智能体」，右「大模型API设置」「内嵌测试示例」「使用说明」。

## 三、判定与评分口径（可复现的关键）

**1. 逐点评估（双维度 checklist）**

| 维度 | 检查项（全部满足=有效） |
|---|---|
| 设计有效性 | ① 有明确控制措施 ② 有责任人和频率 ③ 覆盖关键风险点 ④ 留有可核查痕迹 |
| 运行有效性 | ① 按期执行 ② 有执行证据 ③ 偏差未出现或已整改 |

- 两项均有效 → **有效**；任一无效 → **无效** 并生成候选缺陷；关键证据缺失 → **证据不足** 并计入待补清单。
- 「证据不足」只用于证据确实缺失的情况；若自评已写明具体缺陷事实（如「审批单未归档」），判 **无效** 而非证据不足。

**2. 缺陷三级分类（双标准取高）**

- 定量：涉及金额 < 重要阈值 → 一般；≥ 重要阈值 → 重要；≥ 重大阈值 → 重大（默认 100 万 / 500 万，可在设置区修改）。
- 定性红线（命中任意一条直接判重大）：不相容职务未分离、高管/董事舞弊、管理层凌驾于控制之上、审计委员会或内审机构失效、
  财务报告被出具非标内控审计意见、重大信息未披露、已造成实际损失且无法追回、同一缺陷连续两年未整改。
- 最终等级 = max(定量等级, 定性等级)，**定性红线优先**。

**3. 根因合并**

同一「根因标签 + 责任部门 + 流程」的失效控制点合并为一条缺陷；清单同时保留「关联控制点编号」与「涉及控制点数（合并前数量）」。
缺陷记录表的记录会按「控制点 + 根因」挂接到对应自动候选上，避免同一问题重复计数。

**4. 加权评分**

```
总分 = 100 × Σ(控制点权重 × 有效性得分) / Σ(控制点权重) − Σ(缺陷权重 × 风险值) ÷ 缺陷条数 × 2
```

- 控制点权重：高 3 / 中 2 / 低 1；有效性得分：双有效 1.0、一项无效 0.5、两项无效 0。
- 缺陷权重：一般 1 / 重要 3 / 重大 8（重大 ≥ 一般 5 倍）。
- 风险值 R = 可能性(1–5) × 影响程度(1–5)，R 1–6 低 / 7–14 中 / 15–25 高。
  - 可能性 = 等级基础分（重大 5 / 重要 4 / 一般 3）+ 发生次数加分（≥3 次 +2、2 次 +1），上限 5；
  - 影响程度 = 等级基础分 − 1 + 影响范围加分（涉及 ≥5 点 +3、≥3 点 +2、否则 +1），上限 5。
- 结果保留 2 位小数，**固定四舍五入**（先转整数分值再取尾数，避免浮点误差）；缺陷排序固定为「等级降序 → 涉及金额降序 → 缺陷编号升序」。

**5. 结论判定**

- 存在任意 1 条重大缺陷 → **一票否决，判「无效」**，输出红色预警卡。
- 无重大缺陷：总分 ≥ 80 → **有效**；60–79 → **基本有效（需整改）**；< 60 → **无效**。
- 覆盖率 < 100% 时结论页标注「仅供参考，不可作为年度正式评价」。

> 说明：Prompt 给定的缺陷扣分口径（Σ(权重×R) ÷ 缺陷条数 × 2）本身在缺陷多、等级高时扣分较大，
> 因此总分可能出现负值。这是按 Prompt 公式严格执行的结果，最终结论以「定性判定（一票否决）」为准，不受总分高低影响。

## 四、大模型配置

- 服务商：Finance AI（跃客科技）｜模型：`deepseek-flash`｜Base URL：`https://api.deepseek.com`
- 右上角「**大模型API设置**」可修改服务商 / 模型名称 / API Key（密码框，可显示隐藏）/ Base URL / temperature（固定 0.1）。
- 保存后写入浏览器 localStorage 并立即生效；面板顶部显示当前生效配置（Key 打码为前 4 位 + `****`）。
- 调用方式：`POST {BaseURL}/v1/chat/completions`，`Authorization: Bearer <API Key>`，`temperature 0.1`，`max_tokens 2048`。
- **大模型只做语义归纳与措辞**（判定依据一句话、缺陷根因摘要、评价意见），等级判定、阈值、评分与结论**一律由规则引擎计算**。
- 调用失败（401 / 429 / 超时 / 网络或跨域错误）时：页面提示「大模型调用失败，已切换为规则引擎结果，结论与评分不受影响」，
  规则引擎结果照常输出；可在设置区关闭「启用大模型语义增强」，全程离线运行。
- 默认携带教学测试密钥；正式使用请在设置面板替换为自己的密钥（前端明文存储密钥存在风险，仅保存在本机浏览器）。

## 五、数据与隐私

- 三份材料（控制点清单 / 内控自评表 / 缺陷记录表）解析后仅保存在浏览器内存与 localStorage，**不上传到除大模型 API 之外的任何服务器**。
- 页面上有明确小字说明；「清空全部材料」可一键删除本地缓存。
- 每次操作写入本地操作日志（可在左栏「操作日志」查看并下载 `useractivity.log`）；每次评估保存一条结论摘要（「历史评估记录」）。

## 七、二次开发与重新构建

```bash
# 修改 src/ 下任意文件后，重新生成 index.html
node build.js

# 自检（构建产物语法、禁用词、外链、规则引擎行为、可复现性）
```

## 八、已知边界

- 一次只评一个主体、一套控制点（不提供多公司多年度批量模块）。
- 不连接企业后端数据库、不做实时业务系统对接；网页信息采集不实现自动爬虫（如需参考同行业表述，请手动粘贴文本导入）。
- 内置法规条款仅收录确有原文的条款；条款号无法确证的展示为「相关条款（以正式文本为准）」，不臆造条款号。
- 内部制度未内嵌正式文本，默认使用占位条款并提示「以集团正式文本为准」；可在「内部制度补充」粘贴真实条款替换。
- 「Excel 导出」依赖内联的 SheetJS；PDF 通过浏览器「打印 → 另存为 PDF」实现（跨浏览器排版可能略有差异）。
